# 初赛 Agent

参赛入口使用对外发布的 v1.3 HTTP API。策略根据公开的进度、背包、方块和实体观测执行一条动作，再根据返回结果重新决策。

## 运行

在 `mc-agent-api` 目录下复制 `examples/competition.config.example.json` 为 `examples/competition.config.json`。填写裁判公布的开始时间和本岛中心与半径。时间用带时区的 ISO 8601 字符串或 Unix 毫秒，中心用 `[x,z]`，半径单位为格。规则文件路径相对于配置文件。设置环境变量 `MC_AGENT_USER`、`MC_AGENT_PASSWORD`，或提供 `MC_AGENT_TOKEN`。

```sh
npm run compete -- examples/competition.config.json
```

进程等到开赛时间再登录。默认在开赛八小时后结束。复测时可通过 `durationSeconds` 缩短时长。结束时读取最后一次进度，使用账号密码登录创建的会话会登出。中断时会尝试停止仍在执行的动作。

## 决策和计分

- 基础路线从可见木材开始，合成工作台和木镐，再获取石器、熔炉和铁制装备。观测到资源时追加钻石、黑曜石、钓鱼、附魔、睡眠等进度。饥饿、敌对实体和危险地形会改变动作优先级。
- `RULES.md` 中标为「计分」的行直接启用。把赛方确认的条件项 ID 填入 `confirmedAdvancements` 后，策略才会按该项计分。村民交易使用观测到的可支付报价。
- 日志中的原始分按服务端返回的 `completed_at` 计算，排除比赛时间之外的进度并按 ID 去重。最终成绩以裁判记录为准。
- 方块查询按资源类别分组，短时复用结果。移动后按位置刷新，挖掘前复查目标。探索只选本岛内通过公开接口确认有支撑的落点，执行前再次校验目标坐标。实际寻路由赛事服务负责，当前路线集中在主世界。

`npm test` 可离线验证规则解析、时间窗口、边界检查和基础开局路线。
